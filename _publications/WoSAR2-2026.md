abstract: 'This paper presents an empirical assessment of software aging and rejuvenation using the TrainTicket benchmark deployed under multiple microservice configurations. We evaluate the combined effects of service replication, HTTP  pooling, and measurement-based bucket rejuvenation policies including earlier rejuvenation thresholds, per-replica rejuvenation, and replica switching. 
The experiments monitor response time, Goodput/sec, CPU utilization, memory consumption, and a composite Power (Goodput/Response Time) metric that captures the trade-off between throughput, failures, and response time. 
The results demonstrate that software aging persists in microservice applications despite containerization and replication. Replication alone delays but does not eliminate performance degradation,
while HTTP  pooling substantially reduces the communication overhead associated with HTTP connection set-up and improves long-term performance. Among the evaluated rejuvenation strategies, independent per-replica rejuvenation and switching, with 2 replicas for all services, combined with HTTP  pooling  achieves the highest Power metric values.
